---
title: Manage your workspace
description: Manage forms, folders, and reusable validation rules.
---

**Workspace** has **Forms** and **Validations** tabs. **Forms** organizes complete form documents. Use the **Fields** panel instead when you need to
reorder or group fields inside the active form.

## Create a form

1. Open **Workspace** in the sidebar.
2. Select **Create Form**.
3. Optionally enter a name. Leave it empty to use **New form** for a blank form or the selected example's title.
4. Choose a **UI Library**, or leave it empty for Vanilla.
5. Click **Start with a blank form** or an example under **Quick Start** to create the form.

The selected UI library determines the available fields and cannot be changed later. Leaving it
empty uses Vanilla with native HTML controls. Every example uses the library selected above it.

To create a form inside a folder, open the folder's **Options** menu and select **Add Form**.

## Organize forms with folders

Select **New folder** to create a top-level folder. To nest one, open a folder's **Options** menu and
select **Add Folder**. Select a folder row to expand or collapse it.

Organize forms by project, team, purpose, or another structure that makes them easy to find. An
expanded folder with no contents displays **No forms yet**.

## Open and find forms

Select a form in the Workspace tree to make it active. Its row can show the UI library and field
count.

Use the Workspace filter to search form and folder names. Matching folders and the path to matching
forms remain visible. Clear the filter when no results appear unexpectedly.

## Rename an item

1. Open the form or folder's **Options** menu.
2. Select **Edit Name**.
3. Enter the new name and save it.

Renaming a form changes its document name in Workspace. It does not change any field label or key.

## Delete an item

Open the form or folder's **Options** menu and select **Delete**.

Deleting a form removes only that document. Deleting a folder also removes every form and nested
folder it contains, so review its contents before confirming.

Forms and folders are stored in the current browser. See
[Save, import, and export](/guides/save-import-and-export/) before clearing browser data or moving to
another device.

## Reuse validations

1. Open **Workspace → Validations** and select **Create validation**.
2. Enter a unique **Rule name**, a **Valid when** condition, and an **Error message**.
3. Select **Save validation**.
4. Select a field, open **Validation**, and choose the saved rule from the **+** menu beside **Custom Validation**.

For example, `minimumAge` with `control.value >= 18` and “Enter 18 or more.” can be used on
number fields in several forms. Saved rules are available across UI libraries in this workspace.
You can create them before creating a form.

Selecting a saved rule copies it into the field. Editing or deleting the saved rule leaves existing
field copies unchanged. You can still create a rule just for one field from **Custom Validation**.
Rules whose names conflict with a field's registered or applied validators are omitted from its picker.

Use the filter to find saved rules, select a row to edit one, or use its delete button to remove it.
The dialog keeps your draft if saving fails. Validations are stored in this browser; clearing browser
data removes the catalog. Rules already copied onto fields remain part of those forms' JSON exports.

The tabs use `/workspaces/forms` and `/workspaces/validations`. Form editor links use
`/workspaces/forms/:formId/fields`, `/field`, or `/preset`. Older Studio links redirect automatically.

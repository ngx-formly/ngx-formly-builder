Use ngx-formly Builder to author and test configurations for the ngx-formly components you maintain.
Embed the builder in your Angular application or configure Studio with your application's field
types, wrappers, defaults, and editable properties.

## Editor configuration and runtime configuration

ngx-formly renders a `FormlyFieldConfig[]` using registered Angular components. The editor adds a
palette and property panels around those configurations. Registering a Formly type makes it
renderable; adding editor metadata makes it available to authors.

Studio's Material profile combines standard Formly controls with custom types such as postal code,
cards, and repeating sections, providing runtime registrations and editor metadata for each.

## Choose a starting point

- **Embed in your application:** [Embed in Angular](/developers/embed-in-angular/), then
  [Builder configuration](/developers/builder-configuration/) for initialization settings and styling.
- **Configure a Studio checkout:** [Set up your editor](/developers/set-up-your-editor/), then
  [configure a UI profile](/developers/configure-a-ui-profile/) and
  [add custom components](/developers/add-custom-components/).
- **Render an existing export:** [Use an exported form](/developers/use-an-exported-form/).

These guides target Angular 22 and Formly 11.x. The embedding guide uses locally packed packages,
matching the isolated package-consumer fixture verified by the repository.
The editor shell in `libs/core` uses `@ngx-formly/builder`. Headless state uses
`@ngx-formly/builder-state`, reusable Material fields use `@ngx-formly/builder-material-fields`,
and editor-only Material adapters use `@ngx-formly/builder-material`. Public APIs remain
provisional until the first public prerelease.

For component authoring and runtime APIs, use the [ngx-formly documentation](https://formly.dev/).

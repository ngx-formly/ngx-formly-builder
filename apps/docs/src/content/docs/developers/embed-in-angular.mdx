---
title: Embed in Angular
description: Install and configure ngx-formly Builder inside an existing Angular application.
---

The package root is headless. Import the ready-made editor and `provideFormlyBuilder()` from
`@ngx-formly/builder/ui` when you want its panels and controls. Your application owns the
routing, styles, initialization settings, and persistence. Studio uses the same component and
provider; you do not need its application shell.

## Install the builder

This example targets Angular 22, Angular Material/CDK 22, and Formly 11. The editor has no PrimeNG dependency.
The public API is provisional. Locally built tarballs provide a reproducible integration path
without depending on npm publication status.

In a checkout of this repository, build and pack the builder:

```sh
pnpm install --frozen-lockfile
pnpm run build:core
mkdir -p packages
pnpm --dir libs/core pack --pack-destination ../../packages
```

Copy the generated `.tgz` file into a `vendor/` directory in your Angular application's repo.
Install it from that application's root:

```sh
pnpm add ./vendor/ngx-formly-builder-0*.tgz
pnpm add @ngx-formly/core@^11
```

Keep Angular packages on matching versions. The root requires Angular core/common/forms,
Formly 11 and RxJS 7.8. Its implementation dependencies are installed with the package.

## Headless embedding

Use the root API with your own controls. No builder stylesheet, Material, Tailwind or CodeMirror
installation is needed:

```ts
import { BuilderEngineService, provideBuilderEngine } from '@ngx-formly/builder';

const providers = [provideBuilderEngine({
  editorType: 'survey-designer',
  libraries: [{
    id: 'survey',
    fieldTypes: [{ name: 'input', displayName: 'Text', defaultConfig: {} }],
  }],
})];
// In a component under this provider scope:
// const engine = inject(BuilderEngineService);
// engine.addForm$('Survey', [], {}, 'survey').subscribe();
// engine.addField('input');
// Render engine.activePreviewFormFields() with your own Formly runtime.
```

Register the provider on a route or a child environment injector and destroy that injector with
its host. Each independent editor needs its own scope and storage namespace. The default store
uses local storage; pass `formStore: YourStore` for another implementation of the exported
`FormStoreService` contract. `autoSave: false` disables automatic edit saves, but creating a form
still writes to the supplied store. See the [store lifecycle guide](https://github.com/ngx-formly/ngx-formly-builder/blob/main/docs/asynchronous-stores.md).

`moveField(id, fromIndex, toIndex)` takes an insertion boundary in the original list. To move a
root field down one position, use `fromIndex + 2`; to move up, use `fromIndex - 1`.

## Optional editor UI

The following sections apply to `@ngx-formly/builder/ui`. Install its optional peers explicitly;
package managers do not install these for headless consumers:

```sh
pnpm add @angular/cdk@^22 @angular/material@^22 ngx-drag-drop@^22
pnpm add codemirror@^6 @codemirror/state@^6 @codemirror/view@^6 @codemirror/lang-javascript@^6 @codemirror/lang-json@^6 @codemirror/lang-markdown@^6 @uiw/codemirror-theme-vscode@^4
pnpm add date-fns@^4 file-saver@^2 js-beautify@^1 terser@^5 zod@^4 tailwindcss@^4
pnpm add -D @tailwindcss/postcss@^4 postcss
```

When migrating from the earlier combined root API, move editor components, `provideFormlyBuilder`,
UI configuration helpers, property editors and theme imports to `/ui`. Engine, model, persistence
and `withValidationExpressions` imports stay at the root. Saved documents and storage keys are
unchanged. The UI reuses the root engine; do not also register `provideBuilderEngine` in that scope.

## Configure global styles

Create `.postcssrc.json` at your Angular application's root:

```json
{
  "plugins": {
    "@tailwindcss/postcss": {}
  }
}
```

Use the packaged stylesheet in your global CSS. It contains Tailwind source and must be processed
by PostCSS:

```css
@layer theme, base;
@import '@ngx-formly/builder/styles.css';

html,
body,
app-root {
  display: block;
  height: 100%;
  margin: 0;
}
```

When embedding in a smaller page region, give that region an explicit height. The builder fills
its container. The stylesheet includes Tailwind base styles, which also affect the host page;
review it alongside your application's existing styles.

Load the icon font in `index.html`, or self-host the same font with its font-face and
`.material-symbols-outlined` rules:

```html
<link
  rel="stylesheet"
  href="https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@24,400,0,0"
/>
```

## Initialize and render the builder

This minimal `main.ts` uses native HTML fields, so no Formly UI profile is required:

```ts
import { ChangeDetectionStrategy, Component } from '@angular/core';
import { bootstrapApplication } from '@angular/platform-browser';
import { FormlyBuilder, provideFormlyBuilder } from '@ngx-formly/builder/ui';

@Component({
  selector: 'app-root',
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [FormlyBuilder],
  template: `<formly-builder class="block h-full" />`,
})
class App {}

bootstrapApplication(App, {
  providers: [
    provideFormlyBuilder({
      editorType: 'customer-surveys',
      autoSave: true,
      autoSaveDelay: 1000,
      showSettings: true,
    }),
  ],
}).catch(console.error);
```

In an existing app, put the provider setup in your application or route configuration and import
`FormlyBuilder` into the page component. The packaged stylesheet supplies the editor theme.
Open **Builder settings** to inspect the values supplied by your host.

To offer your own components, pass `libraries` using a
[UI profile](/developers/configure-a-ui-profile/). Register its runtime dependencies and styles in
the host. Additional fields and feature integrations must come from your application or a separate
library. They are not bundled or re-exported by `@ngx-formly/builder`. The Material fields shown
in Studio are private examples, not installable companion packages.

## Separate builder contexts

For independent editors, register the provider on separate routes with distinct `editorType`
values. Omit the application-level `provideFormlyBuilder()` in this setup. Keep the builder stylesheet at application level:

```ts
import { Routes } from '@angular/router';
import { provideFormlyBuilder } from '@ngx-formly/builder/ui';
import { FormEditorPage } from './form-editor-page';

export const routes: Routes = [
  {
    path: 'surveys',
    component: FormEditorPage,
    providers: [provideFormlyBuilder({ editorType: 'surveys' })],
  },
  {
    path: 'internal-forms',
    component: FormEditorPage,
    providers: [provideFormlyBuilder({ editorType: 'internal-forms', showSettings: false })],
  },
];
```

`FormEditorPage` is a standalone component importing and rendering `FormlyBuilder`, as above.
Each route gets its own editor services and document namespace. A namespace separates browser
storage keys; it is not an authorization boundary. The embedded component itself needs no router.

See [Builder configuration](/developers/builder-configuration/) for styling choices, templates,
and custom persistence. The
[package-consumer fixture](https://github.com/ngx-formly/ngx-formly-builder/tree/main/integration/package-consumer)
provides a complete buildable example tested against packed libraries.
